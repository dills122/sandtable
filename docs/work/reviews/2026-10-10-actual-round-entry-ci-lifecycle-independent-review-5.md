## Official-source checks and filter semantics

[Official xUnit 4.0 release notes](https://xunit.net/releases/v3/4.0.0#Microsoft-Testing-Platform) introduce both MTP display-name options for individual theory rows. Versioned [XunitFilters source](https://raw.githubusercontent.com/xunit/xunit/v3-4.0.1/src/xunit.v3.runner.common/Filtering/XunitFilters.cs) permits multiple simple filter types while guarding against query/VSTest mixing; its display-name documentation requires core4.0+. Versioned [XunitSimpleFilters source](https://raw.githubusercontent.com/xunit/xunit/v3-4.0.1/src/xunit.v3.runner.common/Filtering/XunitSimpleFilters.cs) puts categories in an AND filter, includes in OR groups and excludes in negated OR groups. Therefore A's method include plus display exclusion, and B's method exclusion plus display exclusion, match the intended logical predicates. This source verification cannot replace exact application discovery.

Retained 4.0.1 help lines 264–326 confirms multivalue method/display filters, positive OR, negative AND and beginning/end `*` support. The candidate uses no wildcard. The wording about inability to combine filter families does not prohibit combining these simple categories, as the official source shows.

The preferred implementation is one string per method/name in Python argv, retaining `shell=False`; spaces and parentheses remain a single argument and there is no shell glob expansion. [Official Python subprocess documentation](https://docs.python.org/3/library/subprocess.html#frequently-used-arguments) recommends argument sequences and distinguishes shell expansion. The displayed shell-array examples are explicitly unexecuted sketches; they are not runtime proof or copy-ready definitions of the arrays. DAY-A should implement the recommended structured-list construction and retain each full display name, not comma-join values or shell-expand names.
