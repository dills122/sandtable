## What is genuinely missing versus already implemented

### Cumulative debit is the first necessary new behavior

The current `PaidWorld` precondition rejects CP4. Merely relaxing it would lose prior expenditure because its write is `Cp(cost)`, not `Cp(before+cost)`. The changed commitment must atomically carry beforeCp4/afterCp9 and beforeCp0/afterCp3, both ammo10→0, attack and target-use history, no RNG. No debit excess-CPA DP is due for4+5=9. Prove existing Movement CP and origin/causes persist and exact commit retry charges once. Reject changed resources/strength/Cohesion/CPA before a fresh commitment. Certification at initial choice and precommit must agree.

The selected new admitted boundary is exactCP4/0, not arbitrary movement expenditure. Future CP5/7 thresholds, overspend/readiness variants are separate admission requirements; independent policy probes may preserve their original requirement evidence without claiming they are new actual roots.

### Selected settlement arithmetic is already present

`Project` already supports both roles, refused/fulfilled retreat, capture subset and one-TOE guard transfer versus escape, current CP mandatory retreat, lossDP/RP and original relationships. Its guard record retains donor operational/ammo/readiness; guard/escape future duties survive closure. The return-to-original-geometry I01 route preserves the selected retreat/custody topology, so a bounded successor can reuse the complete existing coordinate/handler catalogue rather than design new combat rules.

Nevertheless the code currently calls `PaidWorld(ctx)` repeatedly and that function is CP0-only. All projection/certification calls must use the same new cumulative paidWorld; a mixture of old and new debit helpers would silently reset resources at settlement. The whole selected result catalogue and every handler/window/closure/capacity must be validated on the new frame. Neither unchanged tables nor four seed1 root traces alone prove this.

New paid controls still need complete prospective support for conditional ninth draw/rejection sampling/cursor bounds and all data shapes. The actual I01 seed1/cursor2 witness may remain an eight-draw case; that never licenses removing capture/refusal support or advertised bounds. Do not synthesize a new authentic source by replacing result/RNG with an isolated support row.

### Paid continuation has reusable arithmetic but missing source certification
