# Moved-repeat Breakdown capacity: authentic replay proof packet

Status: investigation, **not** a capacity certificate. Decision owner: Brain. On 2026-10-16 the user selected keeping the frozen 256 MiB Source cap and building a bounded authentic replay proof. The private checkpoint remains `closureFrozen=false`; publication and merge stay blocked.

## Question and proof rule

Can the unchanged native consumer replay every supported valid R02-to-Breakdown Source within the frozen cap and a hosted four-CPU/16-GiB runner's memory and latency budget? A certificate needs either a valid near-reachable-upper-bound ancestry generated by the authoritative transitions, or a reviewed tighter bound proving larger valid Sources unreachable. It must also exercise raw near-cap rejection safely. A large quoted string placed in a Source carrier without valid R02 ancestry is a framing stress test only; it cannot answer the valid-replay question. Do not synthesize or re-sign predecessor events, weaken the supported paid/armed profile, change timeouts, or waive any of the 300 replay cases.

## Bounded next experiment

1. Derive a tighter *reachable valid-state* upper bound from the pinned content, creation/setup grammar, event/ledger counts and each authoritative carrier layer. Identify any caller-controlled field that can reach the generic upper model. The proof must cover both paid and armed paths and every accepted move cut, not merely the retained 300 examples. Check each cited file against the frozen physical manifest.
2. Generate a maximal legal predecessor through the real creation and transition APIs if the tighter bound remains materially above the 885,159-byte fixture maximum. Capture original request and every independent ledger as distinct inputs, then require reference/native bytes, replay, event cuts and retry to agree. Do not alter recorded events or invent ancestry. Start with bounded sizes and stop before any measured process exceeds 4 GiB RSS or aggregate use exceeds 8 GiB; retain every failed attempt and exact input/source hashes.
3. Run a separate near-cap malformed-framing rejection in an isolated process with the same resource ceiling. This covers adversarial raw input, not valid ancestry. Compare native peak and latency against a hosted-compatible four-CPU/16-GiB envelope; run the complete affected CI rows with exact SHA/attempt/process reconciliation only after the valid proof and resource review.

**Unknown:** Whether a valid admitted setup can produce a Source anywhere near 256 MiB, and whether full replay at the true reachable maximum fits the runner. Until either a complete reachable bound or a valid near-bound replay exists, the capacity gate remains open. This packet authorizes no `closureFrozen` change, hosted run, PR or merge.
