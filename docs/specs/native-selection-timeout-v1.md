# Native Selection timeout V38

Bounded native contract; no original-root admission claim.

At initial or repeated unanswered Combat PositionDetermination, explicit System
`combat-selection-timeout` combines deterministic `no-selection` closure with
native progression to Barrage. It is not the isolated C3a closure contract,
which remains at PositionDetermination before its structural continuation.
Existing V13/V32 then record five no-work positions through Reserve Release.
Their predecessor identity is the digest of the explicit System timeout event,
not a fabricated owner Finish offer. Legacy owner V12/V31 bytes remain unchanged.

V38 canonical evidence: campaign, prior version, cycle ordinal (1 initial),
position and successor, acting side, entry hash, World hash, fallback,
configuration hash, opened/deadline/high-water clocks, optional observation and
reason. No owner action, acting element, commitment or target is serialized.
Initial entry hash binds V11 snapshot; repeated entry binds accepted V30
Breakdown and moved World. Replay reconstructs source-legal no-selection from
retained authority, including legal no-attack scope, before byte comparison.

Host accepted step V32 persists deadline from decision entry, never first query.
Reasons: deadline, clock-unavailable, clock-regression, controller-unavailable,
selection-unavailable. Initial unavailable entry has -1 clocks and no observation.
No new dice, ammunition debit, movement or owner choice occurs on timeout.

Validation scope: initial pending selection and genuine second-cycle selection
reached after a paid first assault, reserve release and repeated movement/
Breakdown. First-cycle no-attack retains existing finish-only cycle eligibility;
this packet does not create a missing post-assault random cursor or expand it.
Repeated timeout preserves the actual post-assault cursor, not merely the old
initial V11 snapshot's cursor. Initial entry detection and timeout creation share
supported-content, no-opposing-ZOC and pending-position eligibility checks.

Initial fallback is restricted to the existing infantry-only native no-work
profile at FirstActingSide Position Determination, with idle Breakdown, no open
Reaction and no derived opposing controlled locations. Entry initialization and
cold-entry verification share this eligibility check. Unsupported profiles are
not admitted by adding a timer. Repeated fallback verifies its accepted Breakdown
and source-legal finish projection; no initial snapshot is fabricated.
