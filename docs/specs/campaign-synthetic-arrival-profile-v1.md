# Synthetic arrival profile v1

This is a fixed Core test profile, not a historical scenario or an admitted
campaign setup. Its candidate content starts with the existing repository
synthetic movement fixture, retaining only `movement-contact-lab`, and adds
one independent Axis battalion `axis-arrival-lab`. It is absent from initial
placements and scheduled at turn 1, stage 1, destination `south-west`; no
additional destination or scenario is admitted by this profile. All source
references use the repository synthetic source index. The start-world and
arrival contribution still follow the candidate contracts.

The rules binding uses the current repository ruleset manifest hash. The
synthetic policy binding hashes the UTF-8 bytes of
`sandtable.synthetic-arrival-policy.v1:axis:1:1:south-west` with SHA-256; it is
not a historical ruling. Profile resolution accepts only bytes exactly equal to
the repository-constructed canonical identity and their corresponding hash;
a self-consistent but different candidate is rejected. The candidate reader
revalidates content and group references. Its expected identity is fixed to
`sha256:5da77965dd3976d8eb5c9805f6fa8be9d0ead54b70ff28a182f1a783255b3fbb`;
if the repository catalog or ruleset changes the generated bytes, profile
construction fails closed. Preserving the old profile on a future ruleset
change still requires retaining the old inputs or a versioned resolver.

This profile is not wired to campaign creation, Chronicle, observations, or
Host. It does not yet declare all non-land obligations or supply a trusted
phase cursor. Do not treat it as proof that Naval Convoy Arrival can advance,
or store the candidate as a durable authority record. Actual admission needs
versioned setup and event contracts, cold replay, phase obligations and the
existing Host's authenticated owner path.
