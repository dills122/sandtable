## Occurrence and terminal request

Occurrence identifies campaign, game turn, operation stage, relative player phase slot, resolved
acting side and cycle ordinal. Ordinal is explicit. Structural position never supplies a guessed
ordinal, and Movement 1 cannot satisfy Movement 2. Current admitted corpus has turn 1, stage 1,
first relative slot and either resolved actor; schema scalar capacity does not admit more sources.

Request binds source-prefix identity, complete reference identity, execution-start fragment/cut,
initial checkpoint hash and occurrence, rules/configuration identity, requested terminal, schedule
and maximum accepted-transition count. Semantic admission checks all bindings against authenticated
source before execution. A supported terminal and a satisfied terminal are separate predicates.

Terminal carries independent intended occurrence, exact structural position, closure and explicit
`retain-without-maturity` future-obligation policy. Supported closure states are:

- `entry`: authenticated structural entry, including Reserve entry or repeat Movement entry.
- `completed`: current represented completion, such as Reserve completion, Result2 closure or
  released-I Movement completion at the following Breakdown position.
- `resumed`: authenticated Reaction closure returning to phasing Movement.
- `proof-only`: armed continuation proof with no new authority event.
- `phase-finished`: actual cycle finish at Truck Convoy, retaining source occurrence.
- `open`: incomplete represented native control; never substitutes for requested completion.

Historical terminals preserve exact family distinction. Release entry, completed release and
armed proof are different boundaries. Repeat retains source occurrence 1 and active occurrence 2;
finish retains source occurrence 1 with null active occurrence. Released-I Movement completion
uses actual ordinal 2. No reset, reopened control or automatic ordinal increment is invented.

The eight fallback A2 sources support requested closed Reserve Release ordinal 1 but end earlier
at native Result2 disposition/custody. Their exact published transition counts are 16 for retreat
fallback and 20 for custody fallback. Requested terminal remains unsatisfied. B2 can produce
StepLimitExceeded failed children; no fabricated continuation, success, failed-attempt check or
reconstruction/re-adjudication proof follows from this prefix.

Immediate unresolved settlement cannot satisfy completed Result2 closure. Full World retains
custody, guards, replacement entitlements, cohesion causes and future obligations at every cut.
No upkeep, maturity, training, replacement or operation-stage crossing is supported.

## Source document and full native lineage

Source stores root and ordered, closed-tag native fragments once. Creation root contains exact
Request and Created canonical bytes. Preamble, Weather, stage-entry and Reserve-designation event
fragments reconstruct root with native readers. Events contain native trusted inputs; those inputs
are also retained explicitly in each fragment. Synthetic root instead contains exact C3 Boundary
and has null creation artifacts.

A fragment binds closed family tag, optional exact native base/proof, input and event arrays and
optional terminal native control. Tags are not caller-selected codec names. Every admitted fragment
is generated and authenticated by its pinned family reader, then exact stored bytes are compared
with that source. Caller-supplied matching hashes never replace source authentication.

The 28 historical histories contain 588 post-creation authority events. Extraction preserves all
nine native family chains: ordinary no-attack, direct Reaction closure, active Reaction fallback,
Reaction Movement completion, Reserve cycle entry, inherited release, armed proof, cycle control
and released-I Movement completion. Reaction completion retains and compares exact second-move
predecessor pack before invoking its case-based reader. Released-I completion retains exact nested
control, Movement and completion bases, inputs and events. Native versions and proof-only fragments
remain distinct. Embedded predecessor copies are bindings, not additional transcript transitions.

Never build transcript by collecting receipt summaries. Full source history is ordered original
native bytes; RootSnapshot receipt summaries only serve the independently verified normalization
comparison. Native terminal World/RNG/cycle/control must match selected Task003 endpoint after full
reconstruction. Both list-shaped `members` and singleton `releaseMember` remain in native controls.

## Initial identity versus full reference identity

`sourceLineageHash` uses domain `sandtable.exercise.source-prefix.v1` and includes lineage/profile,
closed side surface and capability family, root, native fragments through execution start, exact fragment/local cut and actual initial native
control. At an open execution fragment, retain only inputs/events through that cut and its actual
initial control. Future fragment bases, terminal controls, suffix events and proofs are excluded.

`referenceTranscriptHash` separately uses `sandtable.exercise.reference-transcript.v1` over complete
retained source material. Reference includes future-bearing catalog name and full side source/base;
it is authenticated in full before deriving any prefix. Request and future B2 manifest bind this
identity. Full reference identity does not enter initial checkpoint or source-prefix identity.

Initial identity excludes schedule, controller configuration and future suffix. Same actual branch
with different future seal order, accepted owner timestamp or finish-clock outcome can share initial
checkpoint. Different initial World/RNG cannot pair merely because terminal names resemble one
another. In particular attacker guard CP-limit and escape cases have different initial CP evidence.

All four private digests use `SHA256(ASCII(domain) || 0x00 || canonical-record-bytes)` with
lowercase `sha256:` text. Schema defines `SourcePrefixSeed`, `ReferenceSeed`, `ExecutionSeed`
and `Checkpoint` property order. Execution seed retains exact native input/event strings.

Executed suffix must remain exact supported reference; this separation does not admit arbitrary
catalog extensions. Historical zero-execution source prefix includes complete history, so its
initial and final checkpoint bytes are identical.

## Full checkpoint and continuation

Checkpoint binds source-prefix identity, execution profile/start, actual executed-transition count
and a distinct hash of executed trusted-input/event prefix. It carries full World and RNG, exact
closed-tag native control, authority version/prefix, rules/configuration identity, actual structural
position and closure, and separate source/active occurrences. During bridge Release phase, native ReleaseState carries retained-World identity rather than a
World object; checkpoint takes World from the already completed authenticated Result2 prefix.
All four bridge cuts preserve that exact settled World and RNG, including guards/entitlements.
Native control plus bound full source
retains receipt history, pending windows, choices, reservations, target uses and authority bindings.
Nothing is reconstructed from ordinal guesses, a current-World-only snapshot or aggregate receipts.

Request `initialOccurrence` binds checkpoint `sourceOccurrence`, the source-cycle anchor. Actual
starting active cycle is checkpoint `activeOccurrence`. A historical repeat therefore retains
source ordinal 1 while active occurrence and requested terminal have ordinal 2.

`checkpoint(source, cut)` validates complete source before cached result access and returns a copy.
`read_checkpoint(bytes, source)` verifies canonical framing and exact replay-derived checkpoint at
its claimed cut. `continue_from(source, checkpointBytes, inputs, events)` authenticates checkpoint,
checks exact contiguous suffix and regenerates successor via native replay. Complete native frames
and observations may be cached under full reference bytes after native authentication; source pins
and exact Source admission precede access, and selected frames/views are returned as copies. Missing history,
changed controls, repeated event, duplicate repeat, reordered suffix or foreign checkpoint rejects.

`observe(source, cut)` regenerates exact accepted side observations, owner windows, candidate bytes
and own receipts. `schedule(source, cut, configuration)` considers these public decisions only.
Continuation checking compares both final private checkpoint and regenerated public surfaces.

## Scheduling and trusted input

Schedule contains version, explicit attacker-first or defender-first role order and native retained
trusted-clock policy. Both owners may be eligible only at actual simultaneous force-assignment
slots for one round. Ordering resolves actual actor/defender audiences; it does not widen any legacy
single-owner window. Dual observations share occurrence and structural position; their audience-scoped
round references remain distinct. Else exactly one current audience or System is selected. Absent public decision
means no controller invocation. Historical profile always has no player eligibility.

Clock and actor stay in native trusted input, separate from side proposal/controller payload. B1
retains them exactly; it does not classify emitted authority events as accepted player choices.
B2 must preserve owner-initiated System fallback and rejected outward outcome, while accepted owner
complete-release remains owner intent despite native System event authorship. Retry/no-op cannot
consume a published-transition ordinal.
