# P01 private local host foundation v1

**Status:** bounded, unissuable host foundation for owner-approved Choice L ([decision packet](../design/p01-a2-local-owner-authority-decision-v1.md), merged #299). Choice L approves the local grant-custody trust model and SQLite design direction, not exact A2 opening/input schemas or admission. This store holds no P01 owner opening, action, event, receipt, public alias or admitted campaign. No route or dependency-injection registration uses it. The accepted owner codec remains [P01 owner decision v1](combat-p01-owner-decision-proposal-v1.md); the proposed read/submit design is [A2 owner path](../design/p01-private-owner-path-proposal-v1.md), merged #297. The P01 acceptance freeze and public/native admission gates remain open.

## Trust boundary

The proof owner is the holder of a host-issued, single-use campaign/side grant, **not** a verified person. The operator secret must be provisioned outside browser bootstrap and never returned by a route. The original test-only seed does not import a CreationRequest or trust a caller's checkpoint hash. The separate [A1 physical import](p01-a1-physical-host-import-v1.md) authenticates one pinned cut with Core and stores canonical evidence in an unissuable campaign row. Probe records remain test-only storage primitives. A future A2 implementation cannot call an owner opening until Core derives approved public refs, own participant and visible hex from one readback-verified cut, and the exact A2 schemas and acceptance amendment are separately approved.

## Closed foundation schema

The SQLite database has `application_id = 0x50303146` (`P01F`), `user_version = 3`, `journal_mode = WAL`, `synchronous = FULL`, foreign keys enabled, and a 5-second busy timeout. The exact creator-owned table DDL is pinned, including `CHECK(singleton=1)`; name/type/nullability/primary key/foreign key shape and foreign-key actions are checked independently. Only the expected SQLite autoindexes may exist; triggers, views and extra tables or indexes make the store unavailable. Every connection to an existing store checks private file/directory permissions, application ID, version, WAL mode, integrity, foreign keys and closed schema; each mutation rechecks them while holding the immediate write transaction. A handle opened before later store drift cannot write through it. Unknown database version, application ID, schema change, failed integrity check or any `foreign_key_check` violation is unavailable; there is no automatic migration. Single-host local file, WAL and SHM form one authority unit. File directory must be private to the host user. Recovery cannot copy only the database file while writes continue.

Identifiers are exact lower-case ASCII: campaign ID 1–128 bytes from `[a-z0-9._-]`; authority/request IDs canonical lowercase UUID D form; side is `axis` or `commonwealth`. Hashes are lowercase `sha256:` plus 64 hex. Secrets are 32 random bytes encoded as lowercase 64 hex and stored only as SHA-256 digest of a domain tag, NUL, campaign ID, side, authority ID, generation and secret bytes. Fixed-time digest comparison is required. Probe record bytes are 1–65,536 bytes and never interpreted as P01 input. Over-cap, malformed ID/hash, changed-input retry and unknown version reject before any mutation.

## Transaction order

1. A host-only test adapter seeds an opaque binding for storage tests. The separate physical importer validates Core A1 and same-cut evidence, then inserts the campaign and `a1_imports` rows in one immediate transaction; those rows cannot activate or issue grants. Neither adapter is registered to a route. For test-seeded rows, a new host activation increments `activation_fence` and rotates both the 32-byte lease secret and host-only operator secret in one immediate transaction. Successor operator custody is returned only with the new lease. Every later mutation checks the fence and lease digest in the same transaction; operator operations also require the current operator secret. A stale process holding the prior operator secret cannot reacquire a newer fence. If the activation response is lost before successor operator custody is retained, further operator operations fail closed; recovery/provisioning for that case is outside this package.
2. An operator-secret-authenticated grant issue stores one grant digest and expiry under the current fence and returns the secret once. Redemption atomically consumes the grant digest and writes a new random replacement credential digest for the same stable authority ID. No old grant or prior credential remains usable. A host restart can authenticate the replacement credential from retained digest; an old cookie is not a credential. If redemption commits but its response is lost, the operator may explicitly recover a non-revoked seat: one transaction changes authority ID, advances grant generation and seat epoch, invalidates the lost credential and issues a new one-use grant. A revoked seat cannot use this recovery path. The old and recovered authorities cannot both authenticate. No recovery is inferred from an unauthenticated client retry.
3. Revocation and probe append each use one immediate SQLite transaction and compare campaign ID, activation fence and the same durable `seat_epoch`. Revocation first increments epoch and invalidates the credential; append first commits its probe and retry index, then revocation can advance. No process-local semaphore is authority.
4. Probe append compares expected sequence/head hash, increments sequence once, stores exact bytes and `(campaignId, authorityId, seatEpoch, requestId)` in the same transaction. An exact retry and ambiguous-commit readback verify bytes, hash, authority ID, seat epoch and request ID against the retained request before returning the stored sequence; altered reuse conflicts. Failed readback is unavailable, never inferred success. A stale activation fence cannot append.

The store must be tested after a new process opens the same file, including verified committed probe digest/record-hash readback after a lost response and rejection after physical record corruption, credential replacement, grant recovery, revocation, competing append/revoke order, stale fence and malformed/over-cap inputs. These tests prove storage primitives only. Activation-secret custody after a lost activation response, multiprocess operator handoff and full host-process crash/restart remain open. A future A2 binding/opening/input must use separate frozen schemas and Core replay and must pass the full AC-003/006/007/008 certificate before native/public admission.
